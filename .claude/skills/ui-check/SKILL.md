# ตรวจหน้ากรอกข้อมูล

skill `verify` ตรวจ**สไลด์**กับ**หน้าที่ commit เข้ารีโป** · ไฟล์นี้ตรวจ**หน้าตาและการโต้ตอบ**
สี่ข้อแรกคือบั๊กที่เคยเกิดจริงในโปรเจกต์นี้ ทุกข้อ **`npm run build` ผ่านหมด**

## 1. โฟกัสหลุดทุกตัวอักษร

**คอมโพเนนต์ที่ประกาศอยู่ในตัวหน้า จะเป็น "ชนิดใหม่" ทุกครั้งที่หน้า render**
React ถอด `<input>` ทิ้งแล้วสร้างใหม่ → พิมพ์ได้ตัวเดียวแล้วโฟกัสหลุด
เขียนเป็น**ฟังก์ชันคืน JSX** (`renderCell(row, m)`) หรือคอมโพเนนต์ระดับบนสุดเท่านั้น

ตรวจ — ต้องพิมพ์**ต่อ**ได้หลังย้ายโฟกัส ไม่ใช่แค่ `fill()` ทีเดียว:

```js
await cell.press('Enter');
await p.keyboard.type('777');
const v = await p.evaluate(() => document.activeElement?.value);   // ต้องได้ "777"
```

`fill()` จับบั๊กนี้ไม่ได้ เพราะมันยัดค่าทั้งก้อนครั้งเดียว

## 2. คีย์บอร์ดตันตรงส่วนที่ย่อไว้

ผังนำทางต้องสร้างจากแถวที่ **มองเห็นจริง** ไม่ใช่ทุกแถวใน config
หัวข้อที่ย่อไม่มี `<input>` อยู่บนหน้า ลูกศรจะเล็งไปช่องที่ไม่มีตัวตนแล้วโฟกัสค้าง

```js
await heads.nth(1).click();                     // ย่อหัวข้อที่สอง
const before = await p.evaluate(() => document.activeElement?.getAttribute('aria-label'));
await p.keyboard.press('Enter');
const after  = await p.evaluate(() => document.activeElement?.getAttribute('aria-label'));
// before === after แปลว่าตัน
```

ทุกช่องต้องมี `aria-label` ที่ระบุตัวเองได้ (`"<ชื่อแถว> เดือน<ชื่อเดือน>"`) ไม่งั้นตรวจแบบนี้ไม่ได้

## 3. แถบติดขอบซ้อนกันแล้วเหลื่อม

`SiteNav` สูง **`h-12` คงที่** และห้ามตัดบรรทัด (`overflow-x-auto whitespace-nowrap`)
แถบเครื่องมือของ `/edit` ยึด **`top-12`** ตามนั้น
ถ้า nav ตัดบรรทัดได้ ความสูงเปลี่ยนตามความกว้างจอ → เกิดช่องโหว่คั่นสองแถบ เนื้อหาไหลผ่าน

```js
const h = await p.$eval('nav', (n) => n.getBoundingClientRect().height);   // ต้องเป็น 49 (48 + เส้นขอบ)
```

**แถบ sticky ต้องทึบ** `bg-paper` ไม่ใช่ `bg-paper/95` — โปร่งแสงแล้วเนื้อหาข้างหลังทะลุขึ้นมา

## 4. ลูกศรซ้าย-ขวาในช่องกรอก

ย้ายช่องได้**เฉพาะตอนเคอร์เซอร์อยู่สุดข้อความแล้ว** (`selectionStart === 0` / `=== value.length`)
ไม่งั้นแก้ตัวเลขกลางคำไม่ได้เลย

## 5. จอแคบและมือถือ

```js
// ที่ 1366 (จอออฟฟิศจริง) ตารางทั้งปีต้องไม่ต้องเลื่อนแนวนอน
const s = await p.$$eval('main .overflow-x-auto', (els) => els.map((e) => ({c: e.clientWidth, s: e.scrollWidth})));
// ที่ 390 หน้าต้องไม่ล้นออกนอกจอ
const overflow = await p.evaluate(() => document.documentElement.scrollWidth > window.innerWidth);
```

รู้ไว้: แคบกว่า ~1240px ตารางแต่ละอันเลื่อนแนวนอน**แยกกัน** คอลัมน์เดือนจะเยื้องกันระหว่างตาราง
ยอมรับได้เพราะเครื่องเป้าหมายกว้างพอ — ถ้าจะแก้ ต้องผูก `scrollLeft` ให้ตรงกัน

## 6. สิ่งที่ห้ามพัง

- **`no-print`** บนทุกแถบเครื่องมือและเมนู · `/deck` คือทางออก PDF
- **โทนสีมาจาก `@theme` ใน `globals.css`** อย่างเดียว ห้ามใส่ hex ในคอมโพเนนต์
- ฉลากภาษาไทยยาวและตัดบรรทัดไม่เท่ากัน — วัดความสูงจริงในเบราว์เซอร์ อย่าเดาสูตร
