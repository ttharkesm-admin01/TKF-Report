## 2. ปัญหาที่พบในไฟล์ปัจจุบัน (ระบบต้องแก้ให้หาย)

1. **เลขหัวข้อไม่ตรงกัน** — สารบัญสองไฟล์เหลื่อมกัน 1 ตำแหน่ง และในไฟล์เดียวกันยังใช้ปนกัน
   (สไลด์ 23 เขียน "2.2 งานสวนฯ" แต่สไลด์ 25–30 เขียน "2.3 งานสวนฯ")
2. **ไฟล์ 161 MB** — ภาพเกิน 2 MB มี 18 ไฟล์ ส่งอีเมลไม่ได้
3. **ฟอนต์ปน 7 แบบ** — FreesiaUPC, Angsana New, AngsanaUPC, Cordia New, Browallia New,
   CPF Imm Sook, Times New Roman · ตระกูล UPC มีเฉพาะ Windows ที่ลง Office ไทย
4. **ธีมเป็นค่าเริ่มต้น Office** (accent1 = 5B9BD5 น้ำเงิน) สีเขียวถูกกำหนดทีละกล่อง
5. **บรรทัดสรุปไม่อัปเดตตามตาราง** — เช่นบรรทัด OE เขียน "ม.ค.–มิ.ย." ทั้งที่ตารางมีถึง ก.ค.
6. **แถวที่ไม่มีข้อมูลทั้งปีกินพื้นที่** — เช่นถังเหล็ก 200 ล. เป็น `-` ทั้ง 12 เดือน
7. **คอลัมน์เดือนที่ยังไม่ถึงกางไว้หมด** — เสียพื้นที่ ~40% ทำให้ตัวหนังสือเล็กเกินไป

## 4. กฎเหล็ก

1. **Gemini ห้ามแตะตัวเลข** — โค้ดคำนวณเสร็จแล้วส่ง JSON ให้เรียบเรียงเป็นประโยคเท่านั้น
   ต้องมี fallback เป็นประโยคที่โค้ดประกอบเองเมื่อ API ล่ม
2. **ตารางต้องเป็นตารางจริง ไม่ใช่รูป** — หัวหน้าต้องอ่านและคัดลอกได้
3. **เลขหัวข้อสร้างจาก `config/sections.json` เท่านั้น** — ห้าม hardcode เลขในสไลด์
4. **ห้ามพิมพ์ซ้ำสิ่งที่มีอยู่ในไฟล์แล้ว** — ถ้ายังต้องเปิด Excel มาดูแล้วพิมพ์ลงเว็บ = ล้มเหลว
5. **ย่อรูปก่อนอัปเสมอ** แต่ไม่เกิน 1600px ต้องยังอ่านวันที่บนรูปออก
6. **% และราคาต่อหน่วยห้ามบวกกัน** — ดู `agg` ใน `shared/schema.ts`
7. **อัปรูปต้องเลือกทีเดียวหลายร้อยใบได้** และอัปต่อได้เมื่อเน็ตหลุด

## 11. รูปไม่ผูกกับ Google Drive

ตัดสินใจภายหลังว่า **ระบบอ่านรูปจากโฟลเดอร์ธรรมดา ไม่ใช่จาก Drive โดยตรง**
จึงไม่ต้องรอผลจาก IT ก่อนลงมือทำงานรูป

```
public/photos/<ปี>-<เดือน>/<รหัสบล็อก>/*.jpg
```

`scripts/scan-photos.mjs` อ่านโฟลเดอร์นี้แล้วเขียน `config/photos.json` ให้เว็บใช้
เรียงตาม**ชื่อไฟล์** เพราะวันที่พิมพ์อยู่บนตัวรูป ไม่ใช่ EXIF (ข้อ 6)

Drive กลายเป็นแค่**ทางเลือกหนึ่งในการพารูปมาลงโฟลเดอร์** เท่าเทียมกับ:

- ก๊อปจาก LINE / อีเมล / แฟลชไดรฟ์ ใส่โฟลเดอร์ตรง ๆ
- Google Drive for Desktop ซิงก์ลงมา
- สคริปต์ดูดจาก Drive API (เขียนทีหลังได้ ถ้า IT อนุญาต)

ทั้งสามทางจบที่ไฟล์ในโฟลเดอร์เดียวกัน โค้ดส่วนที่เหลือไม่รู้และไม่ต้องรู้ว่ารูปมาจากไหน
`driveFolderId` ใน `sections.json` จึงกลายเป็นข้อมูลประกอบ ไม่ใช่สิ่งที่ระบบต้องมีถึงจะทำงาน

## 12. ขอบเขตที่ตัดออก: ไม่ต้องรองรับการตรวจสอบ (audit)

ผู้ใช้ยืนยันว่า **ใช้กันเองในหน่วยงาน 3 คน** เป้าหมายมีข้อเดียวคือ
*ได้สไลด์นำเสนอโดยไม่ต้องใส่ข้อมูลซ้ำหลายไฟล์* ไม่ได้ทำเพื่อส่งผู้ตรวจ

จึง**ยกเลิก**ขั้นที่ 7 `validate` ตรวจความครบถ้วน — ไม่ต้องมีระบบบังคับว่าต้องกรอกครบ
ถ้าลืมกรอก ช่องนั้นก็ว่างบนสไลด์ ซึ่งคนกรอกเห็นเองอยู่แล้วตอนดูเด็ค

**สิ่งที่ยังเก็บไว้ ทั้งที่ฟังดูเป็นเรื่อง audit** เพราะมันกันความผิดพลาดในการทำงานจริง
ไม่ได้มีไว้ตอบผู้ตรวจ:

- **`'none'` แยกจาก `null`** — "ไม่มีรายการ" กับ "ลืมกรอก" ต้องแยกกันให้ออก
  ไม่งั้นเดือนหน้ามาเปิดดูแล้วไม่รู้ว่าต้องตามเก็บข้อมูลหรือไม่ต้อง
- **`note` เชิงอรรถ 3 จุด** — เป็นข้อสังเกตที่รอผู้ใช้ยืนยัน ถ้ายืนยันแล้วว่าถูก ลบทิ้งได้เลย
- **บรรทัดสรุปคำนวณสด** — ไม่ได้ทำเพื่อความถูกต้องเชิงบัญชี แต่เพื่อไม่ให้เกิดปัญหาเดิม
  ที่บรรทัดสรุปเขียน "ม.ค.–มิ.ย." ค้างไว้ทั้งที่ตารางมีถึง ก.ค. (ข้อ 2.5)

**หลักตัดสินใจต่อจากนี้:** ถ้าฟีเจอร์ไหนมีไว้เพื่อ "พิสูจน์ว่าข้อมูลถูก" ไม่ต้องทำ
ถ้ามีไว้เพื่อ "ลดการพิมพ์ซ้ำ / ลดโอกาสพลาดตอนทำสไลด์" ทำ
